# Spec: Group chat

Status: approved by Hoan 2026-11-14 (all decisions below are final). Jira: none (owner decision 2026-11-14). Intent: `intent/2026-11-14-group-chat.md`. Plan: `docs/specs/group-chat.plan.md`.

## Goal

Super admins and PTs create named group chats with trainees. A group is a second chat kind next to the one to one coach chat (`features/chat`), modelled on the old trainee DM tables (`dm_*`): its own tables, its own Ably channel, the shared message UI.

## Today (facts the design relies on)

- `chat_conversations` is one row per trainee (`user_id` not null, unique), so groups need their own tables. `chat_messages.sender_role` is `user | admin`, which cannot name one of 50 senders.
- A trainee's coach chat is shared by the super admins and the trainee's own PT (`users.ptAdminId`); `chat-push.ts` scopes pushes with `ptAdminId` and `admin_hidden_users`. Group membership is explicit, so group push does not use that scoping.
- Roles: `admins.role` is `null | 'super_admin' | 'pt'`; null means super admin (`toAdminRole` in `services/admin-scope.ts`).
- `users.ptAdminId` is changed only by `assignTraineePtAction` (`features/pts/services/pt-actions.ts`, super admin only) after creation.
- Trainee-to-trainee DM is off since 2026-11-09 (old data read-only). Group chat must not bring it back.
- Foreign keys are not enforced, so deleting a trainee or an admin must clean child rows by hand.
- Ably key is restricted to `chat:*`; tokens carry per-channel `subscribe` only, nobody publishes from the browser.

| G1  | **Who creates:** super admin and PT. A PT can add only their own trainees (`users.ptAdminId = PT id`) and not hidden by them (`canAdminAccessUser`); a super admin can add any trainee. The picker and the add action enforce the same rule on the server.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| G2  | **Super admins are always members** of every group, labelled "Manager", and cannot be removed or leave. Implemented as implicit membership computed from `admins.role` (null or `super_admin`), so a super admin created later is in every group at once. No member rows for them, except optional per-admin state rows in `chat_group_members` (mute, read cursor) created lazily; such a row never changes membership and is not counted in the member cap. Absent a state row, the super admin's unread counts only messages created at or after `admins.created_at` (no flood of old unread for a new super admin).                                                                                                                                                                                                                                                                                            |
| G3  | A super admin may add other PTs to a group. A PT creating a group is added as an explicit member together with their own trainees; a PT cannot add other PTs. | G4  | **Sending:** everyone can send by default. Per-group switch `managers_only` ("Only managers can send"; managers = super admins + PTs in the group) set by a super admin or the creator PT. When on, trainees read only and the composer shows a banner.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| G5  | **Trainee scope:** trainees see each other's messages and names in the group, but there is no way to open a 1:1 DM: tapping a name or avatar opens nothing (no profile jump, no "message" action). The 2026-11-09 rule stays.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| G6  | **Manage rights ("can manage")** = super admin, or the PT recorded in `chat_groups.created_by_key`. They can add and remove members, rename, change the photo, switch managers-only and hide anyone's message. If the creator PT's account is deleted, only super admins manage. **Dissolve: super admin only**, soft: `dissolved_at` set, data kept, group disappears from every list, sending and token minting stop; a super admin can still open it read-only by id.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| G7  | **Leave and rejoin:** a trainee can leave (`left_at` set, group leaves their list). To rejoin, an admin who can manage must add them again (same row: `left_at` cleared, `joined_at` reset). A PT member can also leave; a super admin cannot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

The loader's real name and source come from the block-user thread and are wired in the core PR once that PR has merged (core waits for it); until then the hook is the only place to change. The UI state is a hint, every send re-checks on the server.                                                                                                                                                                                                                                                                                                                                             |
| G11 | **Push:** each message pushes to all active members except the sender and members with `muted_at` set. Super admins (implicit) are included unless their state row is muted. Delivery and locale reuse `chat-push.ts` (`deliver`, `loadOwnerLocales`, `deliverLocalized`); `/imlang` silent messages push nobody. Push never logs the body.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| G12 | **Unread and seen:** per-member read cursor (`chat_group_members.last_read_message_id`). Unread excludes own messages, system lines, unsent and hidden messages. Own messages show "Seen by N" (members other than the sender whose cursor is at or past the message); tapping opens a sheet listing who.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| G13 | **Message features:** text, stickers (pack and GIPHY, same rules as the coach chat), one photo per message with optional caption, reactions (one per reactor, same emoji list), reply (same group only), edit with history, unsend, `/imlang` silent, report message. Edit and unsend windows reuse the constants of `chat-rules.ts`. Only the author edits or unsends their own message.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| G14 | **Hide:** a super admin or the creator PT can hide anyone's message in the group (`hidden_by_key`); everyone then sees "Message hidden by a manager"; the same people can unhide it. Hiding does not delete the text (reports and moderation need it).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| G15 | **Report:** any member can report another member's message; `social_reports.target_kind` gains `'group_message'` (`target_id` = message id), added after the block / report PRs merge, with the super admin reports page able to open the message in its group.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| G16 | **System lines** (grey, centred, no bubble): member added, member removed, member left, group renamed, avatar changed, managers-only turned on or off, PT-change alert. Stored as `kind = 'system'` rows with a JSON `system_event`; the text is rendered at read time from the event with i18n, so it follows each reader's language.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| G17 | **PT-change alert:** when `assignTraineePtAction` changes `users.ptAdminId` (the value really changes; a re-save of the same value does nothing) and the trainee is an active member of a group, insert a system line in each such group with `audience = 'super_admin'` (only super admins can read it; never in trainee or PT queries, unread, push or "seen"). "Remove" also removes the member (and writes the normal "removed" line). Races: the resolve is a single guarded update (only while unresolved); a second tap or second super admin gets "already handled by <name>". A newer PT change for the same trainee and group marks the older unresolved line as `superseded` and adds a new one. A trainee already outside the group gets no line. |

Events carry ids only (`message`, `message-update`, `read`, `members`), clients refetch, same as the coach chat; polling is the fallback.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

| G21 | **UI:** a "Groups" section in the admin inbox (`/admin/messages`) and in the trainee Messages page; a group thread page, a group info page (members with Manager / PT / trainee label, mute, leave, manage actions) and a create page for admins. ## Permission matrix

| Action                       | Trainee member                               | PT member | Creator PT                               | Super admin        |
| ---------------------------- | -------------------------------------------- | --------- | ---------------------------------------- | ------------------ |
| Read, react, reply, report   | yes                                          | yes       | yes                                      | yes (always)       |
| Send                         | unless managers-only, chat off or restricted | yes       | yes                                      | yes                |
| Edit / unsend own            | yes (windows)                                | yes       | yes                                      | yes                |
| Mute own notifications       | yes                                          | yes       | yes                                      | yes                |
| Leave                        | yes                                          | yes       | yes                                      | no                 |
| Add / remove members         | no                                           | no        | own trainees only (add), anyone (remove) | any trainee and PT |
| Rename, photo, managers-only | no                                           | no        | yes                                      | yes                |
| Hide / unhide any message    | no                                           | no        | yes                                      | yes                |
| Resolve PT-change alert      | no                                           | no        | no (cannot see it)                       | yes                |
| Dissolve                     | no                                           | no        | no                                       | yes                |

A removed or left member loses read access immediately (membership is checked on every read, send and token request).

## Data model (additive only, all new tables)

No existing table changes except the TypeScript enum of `social_reports.target_kind` (a text column, no DDL). New tables may use `notNull` (the incident #121 rule is about adding columns to existing tables). No foreign keys, like the other chat tables.

```ts
chat_groups: {
  id integer pk autoincrement,
  name text not null,                  // 1..60 chars after trim
  avatar text nullable, avatar_updated_at timestamp nullable,
  created_by_key text not null,        // "admin:<id>"
  managers_only integer(boolean) nullable,        // null = everyone can send
  last_message_id integer nullable, last_message_at timestamp_ms nullable, // inbox sort + preview
  last_change_at timestamp_ms nullable,           // bumped by edit / unsend / reaction / hide (poll cursor)
  dissolved_at timestamp_ms nullable, dissolved_by_admin_id integer nullable,
  created_at timestamp_ms not null
}
index (dissolved_at, last_message_at)

chat_group_members: {                  // explicit members + lazy super admin state rows
  group_id integer not null, member_key text not null,   // "user:<id>" | "admin:<id>" (same as push owner_key)
  added_by_key text not null, joined_at timestamp_ms not null,
  left_at timestamp_ms nullable, removed_by_key text nullable,   // removed_by_key null + left_at set = left on their own
  muted_at timestamp_ms nullable,
  last_read_message_id integer not null default 0
}
primary key (group_id, member_key); index (member_key, left_at)

chat_group_messages: {
  id integer pk autoincrement,         // monotonic, the poll cursor
  group_id integer not null,
  kind text enum("message","system") not null,
  sender_key text nullable,            // null for system lines
  body text not null default "",
  system_event text nullable,          // JSON, validated by Zod on write and read
  audience text enum("super_admin") nullable,    // set only on the PT-change alert
  client_id text nullable,             // uuid, null for system lines (SQLite allows many NULLs in a unique index)
  reply_to_message_id integer nullable,
  sticker_ref text nullable, sticker_url text nullable,
  photo_id integer nullable,
  silent integer(boolean) nullable,
  deleted_at timestamp nullable,
  hidden_by_key text nullable, hidden_at timestamp_ms nullable,
  edited_at timestamp_ms nullable, updated_at timestamp_ms nullable,
  created_at timestamp_ms not null
}
unique (group_id, client_id); index (group_id, id)

chat_group_reactions: { message_id, reactor_key, emoji, created_at }  pk (message_id, reactor_key)
chat_group_message_edits: { id pk, message_id, previous_body, edited_at }  index (message_id)
chat_group_photos: { id pk, group_id, message_id nullable, uploader_key, mime, width, height, data blob, size, created_at }
  index (message_id), index (group_id)
```

`system_event` shapes (Zod discriminated union on `type`): `member_added {actorKey, memberKeys[]}`, `member_removed {actorKey, memberKey}`, `member_left {memberKey}`, `renamed {actorKey, from, to}`, `avatar_changed {actorKey}`, `managers_only {actorKey, enabled}`, `pt_changed {userId, fromPtId, toPtId, resolution: null | {choice: "keep" | "remove" | "superseded", byAdminId, at}}`. Names are resolved at read time, so renames of people and language changes show correctly.

## Server rules (the boundary)

- Every admin action calls `requireAdmin()` first (`requireSuperAdmin()` for dissolve and the alert), every trainee action `requireUser()`; all inputs go through Zod; errors go through `services/action-errors.ts`.
- One access function per request builds a `GroupActor` (`{ key, kind: "user" | "admin", adminRole?, isMember, canManage, isManager }`) from the group row, the member row and `admins.role`. Every read, mutation, API route, photo route and Ably token goes through it. Missing group, dissolved group (non super admin), non-member and left member all answer `notFound` (API: 404), so group ids cannot be probed.
- Add members: each id must exist, be a trainee, be in the caller's scope (G1), not already active, and the cap must hold. Bad or out-of-scope ids are skipped with a per-id result, not a partial crash (KAN-39/40/52 lessons: handle missing rows and bad values at the boundary).
- Send: `groupSendBlockReason` (dissolved, left, managers-only, chat off, restricted) then Zod then insert idempotent on `(group_id, client_id)`.
- Group messages never reach a trainee's coach-chat queries and the reverse; `/api/chat/unread` gets an extra `groups` field (total and per group, system and alert lines excluded).
- PT-change hook: `assignTraineePtAction` reads the old `ptAdminId` first, returns without writing when it equals the new value, otherwise updates and then calls `recordPtChangeInGroups(userId, from, to)`; a failure of the alert is logged and never undoes the assignment.

## Out of scope

Floating bubbles for groups (phase 2), trainee-to-trainee DM, calls, typing and presence, search and gallery inside groups, polls, mentions, pins, invite links, more than 50 members, realtime inbox refresh for groups.
